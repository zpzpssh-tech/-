# 올투게더나우 채널 손익 대시보드

네이버·쿠팡 정산 파일을 넣으면 **정산예정금(수수료 빠진 실수령) 기준 매출**을 계산해
보여주는 대시보드입니다. 원가와 고정비를 채우면 영업이익까지 이어서 계산합니다.

## 쓰는 법

1. **네이버 건별 정산내역 엑셀**을 `data/원본/네이버/` 폴더에 넣습니다.
   파일 이름은 자유이며 `2026-09.xlsx`처럼 월별로 두면 관리가 편합니다.
2. **네이버 원가관리 엑셀**을 `data/원본/원가/` 폴더에 넣습니다. (가장 최근 파일 하나만 씁니다)
3. **고정지출·마케팅비 시트**와 **네이버 검색광고 리포트**를 `data/원본/비용/` 폴더에 넣습니다.
   파일 이름에 각각 `고정`, `광고`가 들어가야 종류를 구분합니다.
4. **쿠팡 계정별 엑셀**을 `data/원본/쿠팡/` 폴더에 넣습니다.
   **파일 이름이 곧 계정 이름**이 됩니다. 예: `휴책.xlsx`, `유큐어.xlsx`, `올투게더나우.xlsx`
5. 터미널에서 다섯 줄 실행:
   ```
   python3 scripts/import_costs.py     # 네이버 원가관리 엑셀 → 원가·수량
   python3 scripts/import_expenses.py  # 고정비·광고비 → costs.csv
   python3 scripts/import_naver.py     # 네이버 정산 엑셀 → 매출
   python3 scripts/import_coupang.py   # 쿠팡 계정별 엑셀 → 매출·원가·비용
   python3 scripts/build.py            # → 대시보드
   ```
6. `dashboard/index.html`을 더블클릭해 브라우저로 엽니다. 인터넷 없이 열립니다.

처음 한 번은 `pip install openpyxl`이 필요합니다.
`import_costs.py`를 먼저 돌려야 같은 상품이 이름이 바뀌어도 상품번호로 하나로 묶입니다.

## 원가 계산 규칙

원가관리 엑셀의 `원가` 시트(상품번호·옵션정보·원가)와 월별 주문 시트(수량)를 짝지어 계산합니다.
원가를 붙이는 순서는 아래와 같고, 위에서부터 먼저 맞는 것을 씁니다.

| 순서 | 방법 |
|---|---|
| 1 | 상품번호 + 옵션정보가 정확히 같을 때 |
| 2 | 그 상품번호에 옵션 없는 원가가 있을 때 |
| 3 | 색상 표현만 다를 때 (블랙·블루 등을 지우고 비교) |
| 4 | 그 상품번호의 원가가 딱 하나뿐일 때 |

못 찾은 건은 `data/원가_미매칭.csv`에 수량 많은 순으로 적힙니다. 원가관리 엑셀의 `원가` 시트에
그 옵션을 추가하면 반영률이 올라갑니다. 주문상태가 **취소·반품**인 건은 물건이 돌아오므로 원가에서 뺍니다.

## 손익 계산 규칙

모든 채널을 **총매출(수수료 빼기 전)** 기준으로 맞춰서 비교합니다.

| 단계 | 계산 |
|---|---|
| 총매출 | 고객이 결제한 금액 |
| − 판매 수수료 | 네이버·쿠팡이 떼 가는 몫 |
| = **실수령 매출** | |
| − 상품 원가 | 옵션별 원가 × 판매 수량 |
| = **상품 마진** | 팔아서 남은 1차 이익 |
| − 물류비 | 택배비, 로켓그로스 입출고비 |
| − 판매자 할인쿠폰 | 로켓그로스 계정만 해당 |
| − 광고비 | 계정별 실제 광고비 |
| = **부가세 내기 전** | 통장에 남는 돈 |
| − 부가세 | (총매출 − 위 비용들) ÷ 11 |
| = **남는 돈** | 그 계정 장사만 놓고 본 실질 영업이익 |
| − 회사 공통 마케팅비 | `costs.csv`에서 계정이 빈 마케팅비 |
| − 회사 고정지출 | `costs.csv`의 고정지출 |
| = **회사 영업이익** | |

### 채널별로 원본 기준이 달라 맞추는 부분

| 채널 | 원본 매출 기준 | 수수료 | 물류비 |
|---|---|---|---|
| 네이버 | 정산예정금(수수료 뺀 뒤) | 정산기준금액 − 정산예정금액으로 되살림 | 주문 × 택배 단가 |
| 쿠팡 로켓그로스 | 총매출 | 그로스부대비용의 실제 수수료 | 입출고비&배송비 실제값 |
| 쿠팡 판매자배송 | 총매출 | **설정값 (자료 없음)** | **주문 × 설정 단가** |

쿠팡 판매자배송 계정(올투게더나우)은 수수료 10.6%, 택배비 건당 2,400원으로 계산합니다.
매출에 고객이 낸 배송비가 포함돼 있어 우리가 내는 택배비를 따로 뺍니다.
로켓그로스 계정(휴책·유큐어)은 부대비용 시트의 입출고비&배송비가 곧 물류비입니다.

### 네이버 수수료는 두 번 빠지지 않습니다

네이버 정산 파일의 `정산예정금액`은 수수료가 이미 빠진 금액입니다.
쿠팡은 수수료 빼기 전 총액으로 들어와서, 두 채널을 같은 잣대로 보려고
네이버도 `정산기준금액`으로 총매출을 되살린 뒤 그 수수료를 도로 뺍니다.

```
총매출(정산기준금액) 1,198,431,060
− 판매 수수료           86,367,221
= 실수령 매출        1,112,063,839   ← 정산예정금액과 정확히 같음
```

이익 계산은 실수령 매출에서 시작합니다.

### 부가세

매출과 원가·물류비·광고비·수수료가 **모두 부가세 포함 금액**입니다.
그래서 부가세 = (총매출 − 그 비용들) ÷ 11 로 계산해 따로 뺍니다.
회사 고정지출은 인건비 비중이 커서 매입세액을 반영하지 않았으니, 실제 납부액은 이보다 조금 적습니다.
`data/settings.json`의 `부가세.적용`을 `false`로 두면 부가세를 빼지 않습니다.

쿠팡 월별 시트에는 상품 구분이 없어, 그 달의 원가는 **상품별 자료가 있는 달의 원가율**을 적용해 추정합니다.

| 섹션 | 무엇을 보나 |
|---|---|
| 계정별 손익 비교 | 네이버·쿠팡 계정을 같은 잣대로 나란히 |
| 손익 단계 | 매출에서 무엇이 얼마씩 빠져 얼마가 남는지 |
| 일별 손익 | 하루하루 매출·원가·택배비·광고비와 남는 돈 |
| 온라인 셀러 필수 지표 | 객단가, 주문당 남는 돈, 광고비 비율, CPA, ROAS, 재구매율, 취소율 |
| 옵션별 판매량과 다음 달 예상 | 재고 발주용. 옵션 단위 월별 판매량과 예상 수량 |

| 상품별 매출 | 상품 단위 매출과 이익률 |

### 다음 달 예상 수량 계산

자료가 온전한 최근 3개월 판매량에 가중치를 줍니다. 지난달 3, 그 전달 2, 그 전전달 1의 비율입니다.
자료가 며칠뿐인 달(예: 9월 1일치)은 계산에서 뺍니다. 셀러 지표의 전월 대비 화살표도 같은 기준입니다.
최근 흐름을 더 크게 반영하려는 것입니다. 발주 제안은 여기에 리드타임 개월 수를 곱한 값이며,
**현재 재고는 반영되지 않으므로 재고를 빼고 발주**해야 합니다.

### 셀러 지표 판정 기준

| 지표 | 좋음 | 보통 | 주의 |
|---|---|---|---|
| 광고비 비율 | 20% 이하 | 30% 이하 | 30% 초과 |
| 주문당 광고비 (CPA) | 객단가의 25% 이하 | 40% 이하 | 40% 초과 |
| ROAS | 손익분기의 1.3배 이상 | 손익분기 이상 | 손익분기 미만 |
| 재구매 고객 비율 | 25% 이상 | 15% 이상 | 15% 미만 |
| 주문 취소율 | 5% 이하 | 10% 이하 | 10% 초과 |

재구매율은 정산 파일의 구매자명 기준이라 동명이인은 한 사람으로 셉니다. 대략치로 보세요.

### 택배비

정산 파일에 배송 방식(N배송/판매자배송) 구분이 없습니다. `data/settings.json`의
`택배비.N배송비율`(0~1)에 실제 비중을 넣으면 두 단가를 섞어 계산합니다.
2026년 1~8월은 대표 확인으로 **전량 N배송(₩3,280)** 을 적용했습니다.

```json
"택배비": { "N배송단가": 3280, "판매자배송단가": 2400, "N배송비율": 1.0 }
```

### 원가를 못 찾은 옵션 채우기

원가관리 엑셀을 직접 고치지 않고도 `data/원가_추가.csv`에 줄을 더하면 됩니다.
`import_costs.py`가 이 파일을 읽어 엑셀 원가에 얹습니다.

```
상품번호,옵션정보,원가,메모
5799070116,✅ 족부 아치 깔창 1쌍: L(250~275mm),500,대표 지정 2026-09-02
```

옵션정보는 `data/원가_미매칭.csv`에 적힌 문자열을 그대로 복사해 넣어야 붙습니다.

## 매출 계산 규칙

네이버 건별 정산내역의 **정산예정금액**을 합산합니다. 정산상태별 처리는 아래와 같습니다.

| 정산상태 | 처리 | 이유 |
|---|---|---|
| 빠른정산 | ＋ 더함 | 실제로 돈이 들어온 건 |
| 일반정산 | ＋ 더함 | 실제로 돈이 들어온 건 |
| 빠른정산 회수 | － 뺌 | 먼저 받은 돈을 네이버가 도로 가져감 |
| 정산후 취소 | － 뺌 | 정산받은 뒤 고객에게 환불해 줌 |
| 정산전 취소 | 제외 | 돈을 받은 적이 없는 건 |

- 정산예정금액은 **네이버 수수료가 이미 빠진 금액**이라 대시보드에서 수수료를 다시 빼지 않습니다.
- 날짜는 **결제일** 기준입니다.
- 정산 파일에는 판매 수량 칸이 없어 **상품주문 한 줄을 1개**로 셉니다. 옵션으로 2개 산 주문은 적게 잡힐 수 있습니다.
- 주문 건수는 주문번호 기준으로 중복을 제거해 셉니다.

`products.csv`는 누적 매출이 큰 상품이 맨 위에 오도록 정렬되며 변환할 때마다 다시 만들어집니다.
`참고_이름수`는 그 상품이 정산 파일에서 몇 개의 이름으로 나타났는지를 뜻합니다.
| `data/costs.csv` | 직접 입력 | 월별 고정지출·마케팅비 |
| `data/settings.json` | 직접 입력 | 계정별 수수료·건당 택배비 |

`products.csv`의 상품코드는 한 번 정해지면 유지됩니다. 새 정산 파일에 새 상품이 나오면
자동으로 코드가 붙고, 이미 채워 둔 원가는 지워지지 않습니다.

## 영업이익까지 보려면 더 필요한 것

1. **월별 고정비와 광고비** — 인건비, 창고·사무실, 물류 솔루션, 채널별 광고비 (`data/costs.csv`)
2. **건당 택배비** — 실제 지급하는 택배 단가 (`data/settings.json`)
3. **원가 미매칭 옵션** — `data/원가_미매칭.csv`의 옵션을 원가관리 엑셀에 추가
4. **쿠팡 계정 정산 파일** — 쿠팡용 변환기를 추가해 같은 규칙으로 합산합니다

## 폴더 구조

```
data/원본/네이버/   정산 엑셀 원본을 넣는 곳
data/원본/원가/     원가관리 엑셀을 넣는 곳
data/              변환된 CSV와 설정
scripts/           import_costs.py, import_naver.py, build.py
templates/         dashboard.html (화면 디자인·계산 로직)
dashboard/         index.html (완성본, 브라우저로 여는 파일)
```

## 일별 손익

날짜별로 매출, 상품 원가, 택배비, 광고비를 빼고 남는 돈을 보여줍니다.
회사 고정비는 빠지지 않은 값입니다. 광고비는 네이버 리포트의 일별 총비용을 그대로 씁니다.

매출은 정산 기준(결제일), 원가는 주문 내역 기준이라 날짜가 하루 이틀 어긋날 수 있습니다.
하루 단위로는 튈 수 있으니 주 단위 흐름으로 보시는 편이 정확합니다.

## 계정 선택

맨 위 첫 번째 버튼 줄에서 **전체 / 네이버 / 휴책 / 유큐어 / 올투게더나우**를 고를 수 있습니다.
고르면 KPI, 손익 단계, 셀러 지표, 일별 손익, 월별 손익이 그 계정 기준으로 다시 계산됩니다.

계정 하나를 고르면 손익 단계가 **'남는 돈'에서 끝납니다.** 회사 고정지출과 공통 마케팅비는
전 채널이 함께 쓰는 비용이라 계정별로 나누지 않습니다. 회사 영업이익은 '전체'에서만 나옵니다.

부위별 매출, 상품별 매출, 옵션별 재고 예측은 **네이버 자료에만** 있어서
네이버나 전체를 골랐을 때만 보입니다. 섹션 제목 옆에 '네이버' 표시가 붙어 있습니다.
